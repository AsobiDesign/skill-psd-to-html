# 楽天市場向けにコーディングするときの制約

楽天は「どこに貼るHTMLか」で使えるタグがまったく違う。同じ店舗の中でも、
GOLDは自由なのにスマホ用説明文はほぼ素のHTMLしか許されない。**最初に貼り先を
確定させてから書き始める**こと。後から移すと作り直しになる。

## 貼り先ごとの早見表

| 貼り先 | 外部CSS | `<style>` | JS | div/span | class | Flexbox/Grid |
|---|---|---|---|---|---|---|
| 楽天GOLD | ◯ | ◯ | ◯ | ◯ | ◯ | ◯ |
| PC用商品説明文ほか（レベル2） | × | ◯ | 動画埋込のみ | ◯ ※属性制限 | △ | ◯（styleタグ内で） |
| ヘッダー・フッター・レフトナビ（レベル3） | × | ◯ | × | ◯ ※属性制限 | △ | ◯（styleタグ内で） |
| スマホ用の各説明文 | × | **×** | × | **×** | **×** | **×** |
| 商品名・キャッチコピー（レベル0/1） | × | × | × | × | × | × |

つまり実務上は次の3モードになる。

- **GOLDモード** — 普通のWeb制作と同じ。CSS設計もJSも自由。
- **PC説明文モード** — 1つのHTMLの先頭に `<style>` を書き、以降をその中で完結させる。
  外部ファイルに切り出せないので、CSSはHTMLに同梱する。
- **スマホモード** — CSSが一切ない世界。`<table>` と `<img>` の組版で作る。
  デザインの再現は画像化に頼る。

## 楽天GOLD

店舗トップページなどに使える自由なファイル置き場。FTPでアップロードする。

- 公開URL: `https://www.rakuten.ne.jp/gold/{店舗ID}/...`
- HTML・CSS・JS・画像を自由に置ける。フォルダも切れる。
- **商品ページには使えない。** 商品ページからGOLDのCSSを読み込むこともできない。
- `.htaccess` は使えない。レスポンスヘッダーを足す手段が無い。

GOLDページの中だけで完結する分には、制約は普通のレンタルサーバーと変わらない。
PSDからそのまま起こしてよい唯一のモード。

## PC用の入力項目（HTMLレベル）

入力欄ごとに4段階の制限がある。レベルが低いほど厳しい。

| レベル | 対象の入力欄 |
|---|---|
| 0 | 商品名、項目選択肢別在庫用の縦軸・横軸項目名 |
| 1 | キャッチコピー |
| 2 | PC用商品説明文、PC用販売説明文、カテゴリ説明文（上下）、トップ説明文（上下）、決済方法の備考欄(PC)、配送方法の備考欄、送料設定の備考欄 |
| 3 | ヘッダー、フッター、レフトナビ、共通説明文（大） |

押さえるべき点だけ:

- **レベル0** はタグそのものが使えない。`<br>` だけ許される。
- **レベル1** は `div` `span` `p` `table` `img` `style` などがまとめて禁止。
  文字だけ入る欄だと思ってよい。
- **レベル2 / 3** は `<style>` が使える。ただし `<link>` は禁止で、
  **外部cssファイルの読み込みは公式に不可**とされている。CSSはHTMLに直接書く。
- レベル3（ヘッダー・フッター等）では `<script>` が完全に禁止。
  レベル2では動画の貼り付け用ソースとしてのみ `<script>` が認められている。

禁止タグ一覧に `*` が付いているものは「タグは使えるが属性に制限がある」意味。
`div` `span` `table` `img` `a` `p` はこの扱いなので、**タグ自体は使える**。

## スマートフォン用の入力項目

対象: スマートフォン用トップ説明文 / 商品ページ共通説明文 / カテゴリページ共通説明文 /
商品説明文 / カテゴリ説明文。

2022年4月以降のスマートフォン用店舗トップページではHTMLタグ自体が使えない。

### 使えるタグ（これだけ）

`a` `img` `table` `td` `th` `tr` `br` `p` `font` `b` `center` `hr`

`<!-- -->` によるコメントアウトも可。`hr` はスマホ用商品説明文とカテゴリ説明文でのみ。

### 使える属性

| タグ | 属性 |
|---|---|
| a | href, target |
| img | src, alt, width, height, border |
| font | color, size |
| p | align |
| table | align, bgcolor, border, bordercolor, cellpadding, cellspacing, frame, height, rules, width |
| td / th | align, axis, bgcolor, bordercolor, colspan, headers, height, rowspan, valign, width |
| tr | align, bgcolor, bordercolor, height, valign |
| hr | color, noshade, size（商品説明文・カテゴリ説明文のみ） |

`style` 属性も `class` 属性も無いことに注意。色は `bgcolor` と `<font color>`、
配置は `align` と `<center>`、余白は `cellpadding` で作る。**1990年代のHTMLに戻る**。

### 落とし穴

- 閉じタグが要るタグは、閉じないとエラーで登録できない。
- リンクは `https://` のみ。`http://` は不可。
- 半角カタカナは全角に自動変換される。機種依存文字は `〓` になる。
- スマホ用商品説明文の `<img>` は20個まで。
- `<` `>` は `&lt;` `&gt;` で書く。

### 実装の型

横並びは `table` で組み、画像は幅100%で伸ばす。

```html
<table width="100%" cellpadding="0" cellspacing="0" border="0">
  <tr>
    <td width="50%"><img src="https://image.rakuten.co.jp/shop/cabinet/a.jpg" width="100%" alt="説明"></td>
    <td width="50%"><img src="https://image.rakuten.co.jp/shop/cabinet/b.jpg" width="100%" alt="説明"></td>
  </tr>
</table>
```

`width="100%"` を使うと端末幅に追従するので、これがスマホでの唯一のレスポンシブ手段になる。
`align="left"` `align="right"` は画面が崩れるため使わない。

## R-Cabinet（画像置き場）

商品ページ・スマホページで使う画像はここに置く。

- 公開URL: `https://image.rakuten.co.jp/{店舗ID}/cabinet/...`
- **1枚あたり2MB以下**、**横3840×縦3840ピクセル以下**
- 一度の登録は合計4MBまで。同時登録は12ファイル（ドラッグ&ドロップは最大50枚）
- 容量の初期値は出店プランによる。足りなければ有料の容量追加オプション

PSDから画像を書き出したら、2MB / 3840px を超えていないか必ず確認する。
超えると登録の段階で弾かれ、コーディングが完成していても公開できない。

## Webフォントをどうするか

結論から言うと、**GOLDの中でだけ使える**。

| 使う場所 | 可否 | 理由 |
|---|---|---|
| GOLDページ内 | ◯ | 同一オリジンなのでCORSが発生しない。`@font-face` も Google Fonts も通る |
| 商品ページ・スマホページ | × | そもそも `<style>`/`<link>` が書けない（スマホ）、外部CSS読込が不可（PC） |
| 商品ページから GOLD のフォントを読む | × | オリジンが違ううえ、GOLDは `Access-Control-Allow-Origin` を返さない |

`item.rakuten.co.jp`（商品ページ）と `www.rakuten.ne.jp`（GOLD）は別オリジンで、
フォントの読み込みにはCORSの許可が要る。GOLDのレスポンスにその許可ヘッダーは無く、
`.htaccess` も置けないので自分で足すこともできない。**回避策は無い**と考えてよい。

### 現実的な進め方

1. GOLDなら、Google Fontsにあるフォント（Noto Sans JP、Outfit など多数）はCDNで読む。
   自前でwoff2をGOLDに置いても同一オリジンなので動く。
2. 商品ページ・スマホページでフォントを再現したい見出しは、**画像にする**。
   これが楽天では定石。本文は端末の標準フォントに任せる。
3. 小塚ゴシック（KozGoPr6N）などAdobe同梱フォントはWeb配信ライセンスが無い。
   Noto Sans JP に読み替える。見た目の差はほとんど出ない。

## PSDから起こすときの方針

貼り先を確定したら、モードごとに次のように組み立てる。

**GOLDモード**
通常のレスポンシブ実装と同じ。`psd_inspect.py` の `responsive.paired` に沿って
1ファイルで組み、768pxで出し分ける。画像はGOLDに置く。

**PC説明文モード（レベル2/3）**
CSSを `<style>` に全部入れて1ファイルにする。クラス名は他店舗の共通CSSと
ぶつからないよう接頭辞を付ける（例 `.asd-hero`）。画像はR-Cabinetに置く。
`<link>` を書きたくなったら、そこは設計を間違えている。

**スマホモード**
デザインを「画像として成立する塊」に分解する。テキストで出す必要があるもの
（価格・商品名・注意書き）だけHTMLの文字にし、装飾された見出しやレイアウトの
込み入った部分は画像にまとめる。分解の粒度は `psd_export.py --sections` の
出力がそのまま目安になる。画像は横幅を実機の2倍程度（750px前後）で書き出し、
`width="100%"` で表示させると精細に出る。ただし2MB制限に注意。
